## 3. TypeError再発の根本原因分析

### 3.1 問題の発生メカニズム

#### **シナリオ1: ページ遷移時の状態リセット**

1. **ダッシュボードページ**: `onMounted`で`fetchOverview()`が呼ばれる
2. **他ページに遷移**: ダッシュボードコンポーネントが`unmounted`
3. **ダッシュボードに戻る**: コンポーネントが`mounted`される
4. **問題**: `fetchOverview()`が呼ばれるが、API呼び出し完了前に`overview.projects`にアクセスされる

#### **シナリオ2: Piniaストアの状態保持問題**

1. **ページ遷移**: Piniaストアの状態が保持される
2. **ダッシュボードに戻る**: 既存の`overview`が`null`または`undefined`のまま
3. **問題**: `fetchOverview()`が呼ばれるが、完了前にアクセスされる

#### **シナリオ3: コンポーネント初期化の競合状態**

1. **コンポーネント再マウント**: `MonthlyStatsSection.vue`が`onMounted`で`loadData()`を呼ぶ
2. **`loadData()`内**: `fetchOverview()`を呼ぶが、非同期処理が完了する前にテンプレートが`overview.projects`にアクセスしようとする
3. **問題**: `overview`が`undefined`の状態でアクセスされる

### 3.2 現在のコードの問題点

#### **`frontend/src/components/MonthlyStatsSection.vue`（行267-270）**

```javascript
if (props.currentTab === 'overview') {
  // overviewタブ: 既存の方法を維持
  const response = await monthlyStore.fetchOverview()
  overviewData.value = response  // ❌ 問題: responseがundefinedの可能性
}
```

**問題点**:
1. **`fetchOverview()`の戻り値が`undefined`の場合**: `overviewData.value = undefined`になる
2. **エラー時のデフォルト値**: `fetchOverview()`はエラー時にデフォルト値を返すが、コンポーネント側で`null`チェックがない
3. **初期値の設定**: `overviewData.value`の初期値が`null`だが、テンプレート側で`overview.projects`に直接アクセスしている可能性

#### **テンプレート側の問題**

```vue
<div class="text-4xl font-bold text-blue-900">
  {{ overviewData?.total_projects || 0 }} 件  <!-- ✅ これは安全 -->
</div>
```

**確認**: テンプレート側は`overviewData?.total_projects`で安全にアクセスしている

**しかし**: どこかで`overview.projects`に直接アクセスしている可能性がある

### 3.3 修正が必要な箇所

1. **`MonthlyStatsSection.vue`の`loadData()`**: `fetchOverview()`の戻り値を確認して`null`チェックを追加
2. **`fetchOverview()`の初期化**: コンポーネント再マウント時に`overview`が確実に初期化されるようにする
3. **テンプレート側の確認**: `overview.projects`に直接アクセスしている箇所がないか確認
