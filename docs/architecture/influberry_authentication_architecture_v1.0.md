# InfluBerry 認証アーキテクチャ v1.0

## 概要
InfluBerryアプリケーションの認証システムのアーキテクチャ設計書。フロントエンド（Vue.js 3）とバックエンド（Flask）間の認証フローと、想定内エラーの処理について記載する。

## 認証システムアーキテクチャ

### 1. 認証フロー設計

#### 1.1 初期認証チェック
```
フロントエンド起動 → /api/auth/me → バックエンド認証チェック
```

**正常フロー**
- 認証済み: ユーザー情報取得 → ダッシュボード表示
- 未認証: 401レスポンス → ログインページ表示

#### 1.2 想定内エラー（401 Unauthorized）
**設計思想**: 未認証状態は正常な状態として扱う

**動作仕様**
- バックエンド: 401レスポンス + `{"code": "UNAUTHORIZED", "error": "認証が必要です"}`
- フロントエンド: エラーメッセージを表示せず、ログインページを表示
- UX: ユーザーに不要なエラーメッセージを表示しない

### 2. 技術実装

#### 2.1 フロントエンド（Vue.js 3 + Pinia）

**認証ストア（auth.js）**
```javascript
// 未認証状態の正常化
if (response.data.user) {
  // 認証済み処理
} else {
  // 未認証状態（userフィールドなし）は正常な状態として扱う
  this.user = null
  this.isAuthenticated = false
  this.error = null // エラーメッセージをクリア
  return { success: false }
}
```

**401エラー処理**
```javascript
// 401エラーは正常（未認証状態）
if (error.response?.status !== 401) {
  this.error = error.response?.data?.error || 'ユーザー情報の取得に失敗しました'
} else {
  this.error = null // 401の場合はエラーメッセージをクリア
}
```

#### 2.2 バックエンド（Flask + Flask-Login）

**認証エンドポイント**
- `GET /api/auth/me`: 現在のユーザー情報取得
- `POST /api/auth/login`: ログイン処理
- `POST /api/auth/logout`: ログアウト処理（認証状態に関係なく実行可能）

**レスポンス仕様**
- 認証済み: 200 + ユーザー情報
- 未認証: 401 + `{"code": "UNAUTHORIZED", "error": "認証が必要です"}`
- ログアウト: 200 + `{"message": "ログアウトしました"}`（認証状態に関係なく）

## 設定画面の月次目標設定機能

### 機能概要
プロフィール編集セクション内に月次目標設定機能を追加。既存の設定画面機能を保持しつつ、月次管理機能を統合。

### 実装方針
- **既存機能保持**: 請求者情報・支払い情報・パスワード変更機能を維持
- **UI統合**: 既存フォームと同じスタイルで統合
- **機能追加**: 既存機能を破壊せず、追加のみで実装

### 技術仕様
- **配置**: プロフィール編集セクション内
- **UI**: 既存フォームと同じデザイン
- **機能**: 対象月選択、目標入力、保存
- **既存機能**: 一切変更せず、追加のみ

#### 2.3 開発環境設定

**Viteプロキシ設定**
```javascript
// vite.config.js
server: {
  proxy: {
    '/api': {
      target: 'http://127.0.0.1:5001',
      changeOrigin: true
    }
  }
}
```

**環境変数**
- 開発環境: `VITE_API_BASE_URL=` （空文字）
- 本番環境: `VITE_API_BASE_URL=https://influberry.jp`

### 3. 想定内エラーの設計思想

#### 3.1 想定内エラーとは
- **401 Unauthorized**: 未認証状態（正常な状態）
- **目的**: ユーザーに不要なエラーメッセージを表示しない
- **UX**: スムーズな認証フローを提供

#### 3.2 想定外エラー
- **500 Internal Server Error**: サーバーエラー
- **404 Not Found**: エンドポイント不存在
- **ネットワークエラー**: 接続失敗
- **目的**: ユーザーに適切なエラーメッセージを表示

### 4. セキュリティ考慮事項

#### 4.1 CSRF保護
- Flask-WTFによるCSRFトークン検証
- フロントエンドでCSRFトークンを適切に送信

#### 4.2 Cookie認証
- `withCredentials: true` でCookie認証を有効化
- セキュアなCookie設定（SameSite, Secure）

### 5. パフォーマンス最適化

#### 5.1 認証状態キャッシュ
- Piniaストアで認証状態を管理
- 初回認証チェック後の状態保持

#### 5.2 プロキシ最適化
- Viteプロキシによる開発環境でのCORS回避
- 本番環境での直接APIアクセス
