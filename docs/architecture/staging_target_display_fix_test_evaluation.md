### 2.1 タブ切り替え問題の再発

#### 🔴 現在月に設定されるが、直後に前月に戻される

**問題の症状**:
1. ✅ 初期化時に現在月（2025-11）が正しく設定される
2. ❌ 直後に前月（2025-10）に戻される
3. ❌ 最終的に前月タブで停止する

**根本原因の推測**:

1. **`watch`による`lastRotationCheck`の変更検知**
   - `watch(() => rotationStore.lastRotationCheck)`が`lastRotationCheck`の変更を検知
   - 古い`lastRotationCheck`（2025-10-01）に基づいて、前月に戻す処理が実行される

2. **`handleRotationStateChange`との競合**
   - `handleRotationStateChange`が`2025-11`に設定
   - しかし、`watch`が`lastRotationCheck`の変更を検知して、`2025-10`に戻す
   - この競合により、タブが現在月→前月に切り替わる

3. **実行順序の問題**
   - `triggerTabUpdate()`が実行される
   - しかし、その直後に`watch(() => rotationStore.lastRotationCheck)`が実行される
   - `lastRotationCheck`が古いため、前月に戻す処理が実行される

**影響度**: 🔴 **極めて高い（ユーザー体験への大きな影響）**

## 3. 問題の根本原因の特定

### 3.1 タブ切り替え問題の根本原因

#### 🔴 `watch`による`lastRotationCheck`の変更検知との競合

**問題の詳細**:

1. **`triggerTabUpdate()`の実行**:
   - `handleRotationStateChange`が呼び出される
   - `lastRotationCheck`が古い（2025-10-01）ため、現在月（2025-11）を優先
   - `currentMonthTab`が`2025-11`に設定される

2. **`watch`による上書き**:
   - `watch(() => rotationStore.lastRotationCheck)`が実行される
   - 古い`lastRotationCheck`（2025-10-01）に基づいて、前月（2025-10）を設定
   - `currentMonthTab`が`2025-10`に戻される

3. **実行順序の問題**:
   - `triggerTabUpdate()`が実行される
   - しかし、その直後に`watch`が実行される
   - `lastRotationCheck`が古いため、前月に戻す処理が実行される

**評価**: 🔴 **`watch(() => rotationStore.lastRotationCheck)`が古い`lastRotationCheck`（2025-10-01）の変更を検知して、`triggerTabUpdate()`を呼び出し、`triggerTabUpdate()`内で`isLastRotationOlder`が`false`になるロジック（158-167行目）が実行され、前月（2025-10）に設定される**

**問題の詳細な分析**:

ログを見ると:
1. `triggerTabUpdate()`が実行され、`2025-11`に設定される（146-155行目のロジック）
2. しかし、その直後に`watch(() => rotationStore.lastRotationCheck)`が実行される（470行目）
3. `lastRotationCheck`が`2025-10-01`（古い値）のため、`triggerTabUpdate()`が再度呼び出される（473行目）
4. `triggerTabUpdate()`内で、`isLastRotationOlder`のチェックが実行されるが、ログには「⚠️ lastRotationCheckが現在月より古い」のメッセージがない
5. 代わりに、158-167行目のロジックが実行され、`lastRotationCheck`（2025-10-01）を基準に前月（2025-10）が設定される

**根本原因**:
- `triggerTabUpdate()`内の`isLastRotationOlder`チェック（143-144行目）が正しく動作していない可能性
- または、`watch(() => rotationStore.lastRotationCheck)`が、`triggerTabUpdate()`の実行後に再度実行され、古い`lastRotationCheck`に基づいて前月に戻す処理を実行している

## 4. 結論

### 4.1 タブ切り替え問題の再発

#### 🔴 ステージング環境でタブ切り替え問題が再発

**問題内容**:
1. ✅ 初期化時に現在月（2025-11）が正しく設定される
2. ❌ 直後に前月（2025-10）に戻される
3. ❌ 最終的に前月タブで停止する

**根本原因の詳細分析**:

ログを詳しく見ると:

1. **最初の`triggerTabUpdate()`実行（`handleRotationStateChange`から）**:
   - `isLastRotationOlder`が`true`になり、現在月（2025-11）が設定される
   - ログ: 「⚠️ lastRotationCheckが現在月より古い - 現在月を優先」

2. **`watch(() => rotationStore.lastRotationCheck)`の実行**:
   - `lastRotationCheck`が`2025-10-01`（古い値）のため、`triggerTabUpdate()`が呼び出される（473行目）
   - しかし、この時点でのログを確認すると、「⚠️ lastRotationCheckが現在月より古い」のメッセージがない
   - 代わりに、`currentMonthTab`が`2025-10`に変更される

**問題の推測**:
- `watch(() => rotationStore.lastRotationCheck)`が実行される時点で、`lastRotationCheck`の値が変わっていない（同じ`2025-10-01`）ため、`watch`の条件`if (newValue !== oldValue)`（471行目）が`false`になり、`triggerTabUpdate()`が呼び出されないはず
- しかし、実際には`currentMonthTab`が`2025-10`に変更されている
- これは、別の`watch`または別の処理が`currentMonthTab`を変更している可能性がある

**根本原因**:
- `watch(() => rotationStore.lastRotationCheck)`が、`lastRotationCheck`の値が変わらない状態で実行される可能性（初期化時など）
- または、`watch(() => currentMonthTab.value)`が、`triggerTabUpdate()`の実行後に別のロジックで前月に戻す処理を実行している可能性
- `triggerTabUpdate()`の現在月優先処理が、他の`watch`または処理によって上書きされている
