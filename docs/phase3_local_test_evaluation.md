## 3. 発見された問題

### 3.1 Vue警告（軽微）⚠️

**警告内容**:
```
[Vue warn]: Component provided template option but runtime compilation is not supported in this build of Vue. Configure your bundler to alias "vue" to "vue/dist/vue.esm-bundler.js".
```

**影響範囲**: `ProgressBar`コンポーネント

**評価**: ⚠️ **軽微**（機能には影響なし）

**説明**:
- ビルド設定の問題で発生している警告
- 機能には影響しない
- ビルド設定の最適化で解消可能（Phase 3の範囲外）

**対策**:
- ビルド設定の最適化（将来対応）
- または、コンポーネントの実装方法の見直し（将来対応）

**優先度**: 🟡 **低**（機能に影響しないため、緊急対応不要）

### 3.2 API呼び出し回数の確認が必要 ⚠️

**現状**:
```
🔧 新API使用: GET /api/monthly/current  ← 複数回出現
```

**発生タイミング**:
1. 初期化時（`MonthlyStatsSection.onMounted`）
2. 月次切り替え状態チェック時（`monthlyRotation.checkRotationStatus()`）
3. 目標データ変更時（`watch(() => monthlyStore.targets[monthKey])`）

**評価**: ⚠️ **要確認**（ステージング環境で評価が必要）

**説明**:
- Phase 3の実装により、不要な`watch`（`watch(() => projectsStore.projects)`, `watch(() => invoicesStore.invoices)`）は削除された
- しかし、初期化時と月次切り替え状態チェック時に複数のAPI呼び出しが発生している
- ローカル環境のため、ネットワーク遅延やリクエストのタイミングが実際の環境と異なる可能性がある

**対策**:
- ステージング環境でAPI呼び出し回数を確認
- 必要に応じて、初期化時の重複呼び出しをさらに最適化

**優先度**: 🟡 **中**（ステージング環境で評価後に判断）

## 5. Phase 3実装の効果評価

### 5.1 実装済み改善項目

#### ✅ **Step 3-1-1: 複数回のAPI呼び出しの削減**
- **実装内容**: 不要な`watch`（`watch(() => projectsStore.projects)`, `watch(() => invoicesStore.invoices)`）を削除
- **効果**: 
  - ✅ プロジェクト・請求書データの変更時の不要な再取得を防止
  - ⚠️ ただし、初期化時と月次切り替え状態チェック時に複数のAPI呼び出しが発生（要確認）

- **実装内容**: ローカル`loading`を削除し、ストア`loading`のみを使用
- **効果**: 
  - ✅ ローディング状態管理の統一化
  - ✅ スケルトン表示の制御が統一された
  - ⚠️ スケルトン表示時間の測定が必要（ステージング環境で評価）

#### ✅ **Step 3-1-3: データ取得タイミングの最適化**
- **実装内容**: 初期化時のデータ取得を最適化（新APIの使用を徹底）

  - ✅ 新API (`/api/monthly/current`) の使用を徹底
  - ✅ 初期化時にデータが取得済みか確認し、必要時のみAPI呼び出し
  - ⚠️ ただし、複数のコンポーネントからのAPI呼び出しが発生（要確認）
