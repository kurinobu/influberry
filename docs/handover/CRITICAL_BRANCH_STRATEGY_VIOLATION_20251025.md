## 📋 **違反の詳細記録**

### 🚨 **重大なブランチ戦略違反（2025年10月25日発生）**

#### **違反内容**
- **月次管理機能**: 大規模変更（新アプリ追加）なのに**feature ブランチ未使用**
- **直接mainで開発**: ブランチ戦略文書の規定を完全無視
- **staging 環境未経由**: テストなしで本番デプロイ
- **後から同期**: 本来不要な修正作業が発生

#### **影響範囲**
- ❌ **ローカルテストが無意味**: 古いコードでテスト
- ❌ **ステージングテストが無意味**: 古いコードでテスト
- ❌ **本番デプロイがリスク高**: テスト未実施
- ❌ **開発効率の大幅低下**: 後から修正作業が必要

#### **根本原因**
1. **ドキュメント無視**: ブランチ戦略文書を確認せずに開発開始
2. **急いでいた**: 機能実装に集中してブランチ戦略を忘れた
3. **過去の成功体験**: 小規模変更でmain直接デプロイが成功していた
4. **feature ブランチ作成を忘れた**: 大規模変更なのにfeature ブランチを作成しなかった

---

## 📜 **法として遵守すべきルール**

### **ルール1: 大規模変更は必ずfeature ブランチ経由**

#### **適用ケース（絶対遵守）**
- ✅ **新アプリ追加** ← **月次管理機能はこれに該当**
- ✅ **設計構造改善**
- ✅ **認証システム変更**
- ✅ **アーキテクチャ変更**

#### **正しい手順（絶対遵守）**
```bash
# 1. feature ブランチ作成（必須）
git checkout -b feature/monthly-management

# 2. ローカル開発・テスト
# 実装・コミット

# 3. staging 環境でテスト（必須）
git push origin feature/monthly-management
# https://staging.influberry.jp で動作確認

# 4. 問題なければmainにマージ（最後）
git checkout main
git merge feature/monthly-management --no-ff
git push origin main
```

### **ルール2: ドキュメント確認は開発開始前の必須作業**

#### **確認すべきドキュメント**
1. **ブランチ戦略文書**: `docs/requirements/git_branch_strategy_v3.md`
2. **アーキテクチャ設計書**: 該当機能の設計書
3. **実装計画書**: 該当機能の実装計画

#### **確認手順（絶対遵守）**
```bash
# 開発開始前の必須確認
1. ブランチ戦略文書を確認
2. 該当機能の分類を確認
3. 正しいブランチ戦略を決定
4. feature ブランチを作成してから開発開始
```

### **ルール3: 環境別テストフローの絶対遵守**

#### **正しいテストフロー（絶対遵守）**
```
ローカル環境（feature ブランチ）
  ↓ ローカルテスト
  ↓
ステージング環境（staging ブランチ）← 同じコードでテスト
  ↓ ステージングテスト
  ↓
本番環境（main ブランチ）← 同じコードでデプロイ
```

#### **禁止事項（絶対禁止）**
- ❌ **main直接開発**: 大規模変更でmain直接開発は禁止
- ❌ **staging 環境未経由**: テストなしで本番デプロイは禁止
- ❌ **後から同期**: 本来不要な修正作業は禁止
